# Архитектура

## Утверждённые решения и границы

- Astro — основа сайта; TypeScript — логика и структурированные данные; обычный CSS — оформление без обязательной UI-библиотеки.
- Тексты и ссылки отделены от компонентов и удобны для редактирования через веб-интерфейс GitHub.
- Лендинг самостоятельный, адаптивный и не входит в существующее приложение ContentFlow AI.
- Работа ограничена `contentflow-ai-landing`. Не читать и не использовать исходники, конфигурацию, секреты, базы данных или сервисы основного проекта без отдельного разрешения.
- Размещение приложения на Railway не является выбором хостинга для лендинга.
- На текущем этапе создаётся только документация. Astro, зависимости, исходники и конфигурационные файлы сейчас не создаются.

## Предлагаемая будущая структура

Это план для согласования, а не существующие файлы или разрешение создать их сейчас.

```text
contentflow-ai-landing/
├── AGENTS.md
├── MAINTENANCE.md                 # будущая русская инструкция
├── docs/                         # текущая документация
├── src/
│   ├── pages/
│   │   ├── index.astro           # порядок секций лендинга
│   │   └── privacy.astro         # если выбрана локальная страница политики
│   ├── layouts/
│   │   └── BaseLayout.astro
│   ├── components/
│   │   ├── sections/             # секции утверждённой структуры
│   │   └── RequestForm.astro     # единственная форма
│   ├── content/
│   │   ├── landing.json          # тексты, FAQ, подписи и порядок данных
│   │   └── links.json            # публичные ссылки и контакты
│   ├── types/

│   ├── styles/
```

Служебные файлы Astro и пакетов появятся только после отдельного задания на создание приложения. Место серверного обработчика пока не определено.

## Отдельное хранение контента — предложение

Предлагается JSON для текстов и ссылок: его можно редактировать через GitHub без изменения компонентов. TypeScript описывает структуру данных; проверка при сборке должна выявлять отсутствующие поля и некорректные данные. Альтернатива для длинных текстов — Markdown с метаданными. Конкретный формат требуется согласовать до реализации.

Предлагаемый контракт: стабильные идентификаторы секций, заголовки, абзацы, примеры, четыре шага, восемь FAQ, подписи формы и CTA, данные изображений с альтернативным текстом. Контакты и адрес политики находятся в отдельном наборе ссылок. Тексты не дублируются внутри компонентов; секреты не хранятся в контенте.

## Форма и серверная граница

Утверждено: единая форма внизу; все CTA демо и пробного доступа ведут к ней. Поля и правила перечислены в `CONTENT.md`.

Планируемая цепочка: браузер → серверная проверка и защита → согласованный механизм доставки заявки → подтверждение или понятная ошибка. Клиентская проверка помогает пользователю, но не заменяет серверную.

Обязательные будущие проверки: хотя бы один допустимый контакт, обязательное согласие, допустимая цель заявки, корректность заполненных полей, антиспам и ограничение частоты. Обязательность имени, допустимые форматы и длины полей, пределы частоты ещё нужно согласовать.

Cloudflare Turnstile — возможный вариант, а не выбранная интеграция. Сервис доставки, место выполнения обработчика, хранение заявок, сроки хранения и работа с повторными отправками остаются открытыми. Секреты будущих интеграций должны оставаться на сервере и не попадать в репозиторий или клиентский код.

Отправка заявки не создаёт аккаунт, не выдаёт пароль и не подключается к внутренним данным основного приложения. Демо и пробный доступ предоставляются вручную.

## Предлагаемый способ публикации

Предлагается статическая сборка маркетинговой части с отдельным серверным обработчиком формы. Конкретный режим Astro, адаптер, хостинг, домен и процесс публикации выбрать после согласования требований к форме. Сейчас никаких сервисов не подключать и деплой не выполнять.

## Будущая инструкция сопровождения

Перед запуском создать `MAINTENANCE.md` на русском: где править тексты и ссылки в GitHub, как сохранять структуру данных, проверять изменения, просматривать результат и публиковать обновления, как исправлять ошибки и возвращаться к предыдущей версии. Команды и порядок публикации описать только после выбора и проверки реальной инфраструктуры.
